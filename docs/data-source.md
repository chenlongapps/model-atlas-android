- 应用通过 [`ModelRepository`](../app/src/main/java/io/github/chenlongapps/modelatlas/data/repository/ModelRepository.kt) 返回三个本地示例，没有发起网络请求。
- 示例名称、描述和 ID 仅用于展示，不应视为 Models.dev 的实时数据或远程字段约定。

- Models.dev 是计划接入的数据源，尚未确认项目最终使用的端点、数据结构与计价单位。

## 接入前必须核实的事项

| 主题 | 需要确认的内容 |
| --- | --- |
| 端点与响应 | 官方入口、响应格式与顶层结构、提供商和模型的组织方式 |
| 模型标识 | 提供商 ID 与模型 ID 的关系、跨提供商是否唯一、如何生成稳定的列表和持久化标识 |
| 字段映射 | 名称、提供商、描述等展示信息的来源；缺失、空值和未知字段的处理规则，不假设存在同名远程字段 |
| 模型能力 | 能力字段的含义、输入／输出类型、上下文和输出上限的区别，不根据模型名称推断支持情况 |
| 定价 | 币种、计费数量单位、输入／输出及缓存价格的区别、价格适用条件 |
| 更新与缓存 | 数据更新时间是否可得、请求限制、缓存条件、刷新与失败回退策略 |
| 使用条件 | 数据使用许可、来源署名及其他适用要求 |

价格缺失不能表示为零；只有币种和计费单位明确且可比较时，才能展示为同口径价格。缺失信息应与“不支持”“免费”等明确含义区分。

- 在本文记录实际采用的端点、核实日期和官方依据，补充响应结构、字段映射与价格单位；若需保存响应样本，应注明来源与获取时间。
- 核实后同步修正 `README.md` 和 `TODO.md` 中的地址分歧，不保留多个互相矛盾的接入约定。

- 为解析与映射补充正常响应、缺失字段、空值、未知字段和异常响应的测试；实现缓存时补充离线与刷新失败场景。
- 接入和缓存任务的完成状态只在 [TODO.md](../TODO.md) 维护，不因文档或依赖已添加就将功能标记为完成。
